## 2.5 图谱检索服务 + Prompt 模板 + 评测（交付物 ⑤⑥⑦）

### 图谱检索服务（独立 API，交付物⑤）

| 能力 | 端点 | 说明 |
|---|---|---|
| 实体查询 | `GET /v1/graph/entity/{label}/{key}/{value}` | 按唯一键查实体 |
| 关系遍历 | `GET /v1/graph/relations/{entity_id}` | 沿关系找邻居 |
| 多跳推理 | `POST /v1/graph/multi-hop` | 沿关系链推理（支持反向） |
| 关键词检索 | `GET /v1/graph/search?q=` | 全字段搜索（含品类映射） |
| 图谱统计 | `GET /v1/graph/stats` | 节点/关系统计 |

**技术**：Neo4j HTTP API（零依赖）、参数化查询防注入、白名单校验标签/关系类型。

### 四套 Prompt 模板（交付物⑥）

| 场景 | 用途 | 防幻觉 |
|---|---|---|
| customer_service | 客服回答 | ✅ 仅基于检索结果 |
| product_recommend | 商品推荐 | ✅ 不虚构属性 |
| aftersale_policy | 售后政策 | ✅ 严格按政策条款 |
| competitor_analysis | 竞品分析 | ✅ 仅基于检索数据 |

### 检索质量评测（交付物⑦）

- **35 个评测问题**：覆盖商品/政策/FAQ/规则/多跳推理/负例六类
- **实测通过率 100%**（35/35）
- **评测驱动发现并修复**：
  - search 覆盖字段不足 → 加 content/answer/keywords/category
  - 品类中文搜索不命中 → 加 code→中文映射
  - 多跳反向关系不支持 → 加方向支持
  - 数据覆盖缺口 → 补 3 条真实 FAQ（怎么退货/多久发货/物流投诉）

## 3. gbrain 融合部分（本次新增核心）

### 3.1 融合了什么

| gbrain 思想 | 落地实现 | 位置 |
|---|---|---|
| **编译真相 + 时间线** | 每个知识 = 当前结论（可更新）+ 演化历史（只追加，可溯源回滚） | `knowledge_engine/models.py` |
| **三层知识边界** | general / seller / memory 分层，B1b 映射到运行时已有 layer（零 schema 改动） | `runtime_bridge.py` |
| **梦循环** | 增量摄取 / 一致性校验 / 合并记忆 三作业 | `dream_cycle.py` |
| **自动修复** | 一致性校验发现悬空引用/孤立节点 → 自动标记失效（不删数据） | `auto_repair` |
| **定时调度** | Windows 计划任务每天 03:00 自动跑 | `scheduler.py` + 计划任务 |
| **Wiki 渲染** | 知识渲染为可互链词条页（当前结论/属性/相关词条/演化历史） | `wiki_renderer.py` |
| **图谱可视化** | 导出自包含 HTML（浏览器打开即看，无需 Neo4j） | `export_graph.py` |

### 3.2 架构（低耦合、可复用）

```
src/ecommerce_agent/knowledge_engine/
├─ models.py          数据模型（三层边界 + 编译真相/时间线）
├─ loader.py          读任务6产物 → 统一 KnowledgeItem
├─ dream_cycle.py     梦循环三作业 + 自动修复
├─ runtime_bridge.py  接入运行时（B1b：scope→layer）
├─ wiki_renderer.py   Wiki 词条渲染
├─ export_graph.py    图谱可视化导出
├─ scheduler.py       梦循环调度器
└─ verify_system.py   系统质量验证
```

**工程保证**：
- 零第三方依赖（纯标准库）
- 不碰运行时（`knowledge_management.py`/`rag.py` 修改时间未变，全量回归 352 passed）
- 只读任务6产物（绝不改已交付数据，只加层）
- 独立接口（`from ecommerce_agent.knowledge_engine import ...`）
