# 云湃电商一体机 Agent 0.9.0 测试报告

## 1. 结论

- 测试对象：`yunpai-ecommerce-agent 0.9.0`，SQLite schema v9。
- 本地候选结论：**通过**。知识/SOP/质检治理和客服操作闭环达到本地开发、演示、接口联调和影子评测条件。
- 生产放行结论：**不通过（NO-GO）**。未取得真实淘宝客服机器人资质、平台专属凭证、测试店铺、真实顾客脱敏回放集和生产设备长稳证据。
- 本报告不把虚拟连接器、mock TOP 网关或本地性能烟测当作真实平台生产证据。

## 7. 质检与 VOC

规则覆盖：事实证据缺失、模型降级、漏转人工、敏感信息脱敏、渠道发送失败、草稿发送失败和高风险回复发送。

验证结果：

- 每个结果记录规则集版本、问题代码、严重度、证据 ID、分数和记录版本。
- 人工可确认或驳回；确认问题必须提供修正答案/处置说明。
- 旧版本复核请求冲突，不可重复确认。
- VOC 只聚合代码化问题与严重度，不拼接模型 SQL，不自动发布知识或修改 SOP。
- 故障组合样本正确得到 18 分；渠道失败组合正确输出 3 类问题。

## 9. API 与界面

API 负例覆盖未认证访问、知识范围错误、非法生命周期、陈旧版本、非法 SOP DSL、质检目标不存在、渠道会话/草稿不存在。

浏览器实际操作：

- 管理员登录并读取 schema v9、活动 SOP 和经营状态。
- 新建店铺知识草稿，依次评测、批准，最终显示 `active/approved`。
- 对真实本地 Agent 会话运行质检并人工驳回误报，结果显示 `dismissed`。
- 渠道接待页在无真实连接时显示明确空态，不生成虚假店铺或会话。
- 默认桌面视口布局无重叠；390 x 844 下页面无横向溢出，导航和表格在各自容器滚动，表单为单列。
- 浏览器控制台无 JavaScript error。

测试页面：`http://127.0.0.1:8092/admin`。

```text
schema=9
PRAGMA integrity_check=ok
knowledge=157, sop_definitions=2, qa_results=1, sessions=1
backup_bytes=1003520
```

该恢复检查证明 schema 和抽查计数一致，但尚未产品化为带加密、轮换、校验清单和一键恢复的运维命令。

## 11. 生产阻塞项

以下任何一项未完成都不得把 0.9.0 标记为生产可用：

1. 淘宝客服机器人类目审批、AppKey/AppSecret、奇门 customerId、request_token/tenant_id 和测试店铺真实收发。
2. 真实 ERP/OMS 商品、订单、物流、售后数据字典和增量/对账联调。
3. 首个客户的脱敏会话、知识、SOP、质检基线和业务验收口径。
4. 真实模型准确率、SOP 路径命中率、严重事实错误 0 和提示注入回放。
5. 24 小时以上长稳、进程崩溃/断电恢复、磁盘不足、平台限流、密钥轮换和监控告警。
6. 加密备份、保留策略、正式恢复命令与整机恢复演练。
7. 第一个低风险真实写动作的业务批准、dry-run/读回、补偿和资损评审。

## 12. 后续测试顺序

1. 将备份/恢复、对账和不确定 outbox 恢复做成产品命令与管理 API。
2. 补 24 小时本机 soak、强杀恢复、磁盘写满和 checkpoint 恢复测试。
3. 用真实平台沙箱完成入站、暂停竞态、人工改写、回写回执和重复消息回放。
4. 用首个客户脱敏集执行知识准确率、SOP 正常/边界/失败路径和质检一致性验收。
5. 只有全部 Gate 有证据后，才从影子模式进入仅提示，再逐步灰度自动回复。
