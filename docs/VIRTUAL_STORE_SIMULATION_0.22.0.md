# 0.22.0 虚拟店铺运营模拟与验收

## 1. 目标与边界

本版本为现有商品、订单、库存、指标、竞品、客服、客服评测、人工接管和后台模块增加一条可重复的跨模块验收链路。它解决的是“单项测试都通过，但没有一家店的关联数据证明模块能协同工作”的问题。

数据包全部为虚构数据，不含真实顾客、订单、店铺或竞品信息。所有竞品来源标记为 `virtual` 和 `is_estimate=true`，不得作为生产经营结论、客户验收数据或真实平台联调证据。

## 2. 模拟店铺

- 店铺：晴川生活电器旗舰店
- 店铺 ID：`qingchuan-flagship-001`
- 数据包：`src/ecommerce_agent/fixtures/virtual_store_v1.json`
- 商品：6 个在售 SKU，覆盖空气炸锅、吸尘器、加湿器、热水壶和循环风扇
- 库存：10 条杭州/武汉双仓记录，包含断货、缺货、补货和滞销状态
- 订单：8 个订单，覆盖待发货、运输、签收、取消、部分退款和 3 类售后
- 竞品：3 个同款候选，其中 2 个可批准、1 个因型号/容量冲突拒绝
- 内容证据：1 条商品卖点和 2 条聚合口碑摘要，不保存评论者或原始评论
- 店铺知识：商品保修、物流异常、价保和退货 4 条受控知识

固定来源时间和稳定 `source_id` 使重复运行进入现有来源版本契约：同时间同载荷返回 `idempotent`，旧版本和同版本异载荷仍被领域服务拒绝。

## 3. 实现路径

```text
虚拟 JSON 数据包
  -> Pydantic 领域模型校验
  -> Catalog / Inventory / Order / Competitive / Knowledge 服务
  -> SQLite schema v21 事实与审计
  -> Agent 工具、派单 Worker、Admin 聚合读取
  -> 13 个场景断言、模块覆盖审计和结构化报告
```

模拟执行器位于 `src/ecommerce_agent/simulation.py`。它只调用公开领域服务，不直接插入业务表，因此来源版本、同款审批、知识生命周期、租户隔离、工具权限和自动派单约束仍然生效。

管理员 API 位于 `src/ecommerce_agent/simulation_api.py`：

- `GET /v1/simulations/virtual-store`：查看数据包及记录数量。
- `POST /v1/simulations/virtual-store/run`：导入当前管理员租户并运行场景。
- 请求必须显式提交 `confirm_virtual=true`；缺失或为假时返回 422。

CLI 使用当前环境变量对应的数据目录和租户：

```powershell
yunpai-agent simulate-store
yunpai-agent simulate-store --skip-customer-service
```

第二个命令只用于经营数据诊断，会把客服和派单场景标记为跳过，因此不能作为完整验收通过证据。

## 4. 场景矩阵

| ID | 模块 | 模拟需求 | 关键断言 |
|---|---|---|---|
| D01 | 商品 | 查询在售商品与版本 | 6 个 SKU、来源版本完整 |
| D02 | 订单 | 核验订单、物流和售后 | 8 个订单、3 个售后订单、物流异常可见 |
| D03 | 库存 | 识别断货、缺货和滞销 | `stockout`、`stockout_risk`、`slow_moving` 均出现 |
| D04 | 指标 | 计算订单、收入和售后率 | 7 个有效订单、4181.00 元、售后率 0.4286 |
| D05 | 竞品 | 只使用批准同款证据 | 2 批准、1 拒绝，Agent 只返回批准观察 |
| D06 | 竞品监控 | 发现低价并告警 | 12.02% 低价触发持久告警 |
| D07 | 智能客服 | 检索店铺知识 | 正确知识回答，或模型不可用时带证据安全转人工 |
| D08 | 订单 Agent | 查询可信订单 | 正确订单可读，订单号不匹配被阻断 |
| D09 | 人工接管 | 物流异常转人工 | 建单、持久 job、自动派给有效坐席 |
| D10 | 后台 | 查看运行结果 | 会话、消息、知识、任务和审计均可观察 |
| D11 | 租户隔离 | 其他租户查询 | 四个事实域均返回空 |
| D12 | Connector | 更新安全库存缓冲 | 虚拟动作幂等且回执验证通过 |
| D13 | 客服评测 | 冻结虚拟标注集并回放实际 Agent | 数据集哈希固定、评测通过、主库会话/消息/任务零污染 |

## 5. 结构化结果

执行结果包含：

- `loaded`：各领域加载数量和 `applied/idempotent` 状态；
- `scenarios`：每个需求的通过、失败或跳过状态；0.22.1 起同时提供 `input`、`expected`、`assertions` 和 `output`，并保留兼容字段 `detail`；
- `module_coverage`：对模块注册表逐项核对；7 个 `available` 模块必须全部通过，营销和财务保持 `planned_not_executed`；
- `summary`：总数、通过、失败和跳过数量；
- `production_claim=false`：明确阻止把模拟通过解释为生产放行。

执行结束会写入 `simulation.virtual_store.completed` 审计事件，只记录数据包 ID、店铺 ID、汇总和通过状态，不记录密钥或原始顾客对话。

后台 `/admin` 的“场景验收”页面可在明确点击运行后逐项查看这四类证据，具体契约和界面说明见 `docs/VIRTUAL_STORE_EVIDENCE_0.22.1.md`。

## 6. 已知限制

- 营销和利润/对账模块仍是 `planned`，本数据包不能验收尚未实现的领域能力。
- 当前模型默认关闭；D07 验证知识检索和安全降级，D13 验证合成标注集的实际 Agent 隔离回放，二者均不替代真实客户标注和真实模型正确率评测。
- 当前仍是单机 SQLite，不覆盖多节点并发和分布式队列。
- 模拟数据不替代淘宝/ERP 权限、真实竞品来源、客户脱敏标注、24/72 小时长稳、容量、安全或异机恢复 Gate。
