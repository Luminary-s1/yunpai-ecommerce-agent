## 4. 浏览器端到端结果

在 `http://127.0.0.1:8103/admin` 的运行实例完成：

1. 管理员登录并进入智能客服工作台。
2. 启动值守，页面切换为“停止值守”，短租约生效。
3. 将坐席改为按班次接单；未来班次正确显示“班次外”和 0 个可接单。
4. 取消未来班次并新增当前生效班次；页面显示“班次内”。
5. 保存档案后旧心跳会话被清理，再次开始值守。
6. 发送转人工消息，job 入队；后台 worker 自动分配到 `admin-test`。
7. 坐席离线后再次建单，job 进入 waiting，出现“无可用自动坐席”持久告警。
8. 使用正式处置弹窗确认告警。worker 更新告警版本时，旧版本提交显示 409；刷新后重试成功。
9. 恢复值守后 waiting job 自动 assigned，告警自动 resolved。

## 5. 实现中发现并修复的问题

### 5.1 档案保存后的前端心跳状态不一致

服务端保存档案会使旧值守 session 失效，但页面最初仍保留本地定时器和“停止值守”。修复后保存本人档案成功即清理 heartbeat timer/session；停止值守提交冲突时恢复原会话，避免错误丢失客户端续租状态。

### 5.2 原生 prompt 无法完成告警处置

派单重试和告警确认最初使用 `window.prompt()`。真实内嵌浏览器报告 `prompt() is not supported`，操作无法提交。修复为受控对话框，包含对象/锁版本、默认说明、长度校验、提交禁用和服务端错误回显；修复后没有新增浏览器 warning/error。

### 5.3 schema 漂移库不应在校验前执行补种

伪造 v21 迁移标记但缺少 v19 队列表的损坏数据库，若直接补种 job 会先抛出普通 SQL 错误。修复后只有基础任务/队列表存在时才执行补种，随后由统一结构校验返回明确 schema drift 错误。

### 5.4 告警确认存在真实乐观锁竞争

无坐席 worker 会递增告警 occurrence 和版本。浏览器实测在弹窗打开后恰遇新一轮 worker 更新，提交正确返回版本冲突，页面保留错误；刷新并基于最新版本确认成功。这证明并发不会被静默覆盖。

- 尚未完成 24/72 小时长稳、峰值建单/派单容量、时钟漂移和 NTP 故障测试。
- 尚未使用真实客服团队校准技能、容量、班次、SLA 和告警责任人。
- 尚未获得真实淘宝机器人权限、测试店铺、合法竞品/口碑源和真实 ERP/OMS。
- 尚未完成客户标注集、真实模型、设备密钥、异机恢复、安全测试和业务签收。
