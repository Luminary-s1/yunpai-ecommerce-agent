# 0.22.1 虚拟店铺输入输出证据工作台

## 1. 目的

0.22.0 已能执行 13 个关联场景，但报告中的 `detail` 主要是计数和布尔值，无法直接复核“调用了什么、业务系统实际返回了什么”。0.22.1 不改变业务规则和数据库 schema，专门补齐可审阅的逐场景证据。

## 2. 报告契约

`GET /v1/simulations/virtual-store` 返回 `simulation-evidence-v1` 场景定义，包括每项固定输入和预期。`POST /v1/simulations/virtual-store/run` 的每个 `scenarios[]` 元素包含：

- `input`：实际执行所对应的领域服务、Agent、工具或连接器调用参数；
- `expected`：运行前固定的业务验收条件；
- `assertions`：运行后的逐项通过、失败或跳过状态；
- `output`：服务、工具、Agent 或评测运行的实际结构化返回；
- `detail`：为兼容 0.22.0 调用方保留，内容与 `output` 相同。

报告继续固定 `virtual=true` 和 `production_claim=false`。输出只来自显式虚拟数据包和本地运行产生的虚拟会话，不包含真实顾客数据、平台凭证或生产结论。

## 3. 实际输出范围

| 场景 | 输出证据 |
|---|---|
| D01-D04 | 完整商品、订单/物流/售后、库存风险和六项指标对象 |
| D05-D06 | 同款匹配、竞品 Agent 工具输出和持久告警记录 |
| D07 | 客服 Agent 完整响应、来源、上下文快照和安全降级原因 |
| D08 | 获准订单工具返回和越权探测错误 |
| D09-D10 | 客服响应、人工任务、派单作业和后台聚合结果 |
| D11-D12 | 跨租户四域查询结果、连接器首次/重放回执和读回验证 |
| D13 | 冻结评测集、完整评测报告及主运行库前后计数 |

## 4. 后台交互

管理员登录 `/admin` 后进入“场景验收”：

1. 页面先读取 13 个场景定义，但不会自动运行会创建虚拟会话或任务的验收流程。
2. 左侧按模块和状态筛选场景；右侧在运行前即可查看固定输入与预期。
3. 点击“运行全部场景”后，页面展示汇总、模块覆盖、逐项断言和格式化的实际 JSON 输出。
4. 任一失败场景会保留异常类型和错误文本，页面默认选中首个失败项。

这套页面用于代码级候选复核，不替代真实淘宝/ERP、真实模型、客户数据、合法竞品来源、长稳、安全和灾备验收。
