## 4. 测试中发现并修复的问题

### 4.1 高风险业务动作可能被模型回答

首次实际 Agent 20 用例检查发现“把收货地址改成新的”和“取消这个订单”没有稳定保留高风险接管。原因是旧 mock 只识别相邻短语，真实图也只依赖模型是否选择 `act/handoff`。

修复后，图在模型决策之后再次调用集中式高风险检测。业务动作被统一标记为 `high`；若模型返回 `answer/clarify`，强制转为 `business_action_requires_verified_execution`。mock 意图映射同步补齐物流、支付、售后、安全和发票，最终实际 Agent 20/20 通过。

### 4.2 历史测试夹具写死 schema v18

首次全量运行出现 3 个失败，均为灾备和 CLI 测试把当前 schema 写死为 18，并非业务回归。夹具更新为 schema 19 后，相关定向测试 18/18 通过，最终全量 195/195 通过。

### 4.3 390px 队列标题被筛选器挤压

移动端视觉检查发现“人工接管队列”标题被四个筛选框挤成逐字换行。修复为 460px 以下面板头上下布局，筛选框按至少 132px 换行。修复后页面宽 375px、视口宽 390px，无页面级横向溢出或控件重叠；宽表保留面板内部横向滚动。

## 6. 并发、SLA 和失败语义

原子认领同时依赖数据库写事务、任务版本、未认领状态和空负责人条件；并发测试不是先后串行模拟。队列容量在认领和转派事务内检查，活动状态之外的任务不占容量。

SLA 扫描只升级开放任务。首次响应违约形成 L1，解决违约形成 L2；已达到对应级别时重复扫描跳过。扫描期间坐席操作引起版本变化时计入 conflict，不覆盖新状态。worker 默认 30 秒运行一次，启用但线程退出时 readiness 失败。

终态必须有解决说明；备注和事件说明统一脱敏；`input_required -> working` 超过任务重试预算拒绝；终态不能升级或恢复。

## 11. 发布建议

将 0.19.0 用作本地或客户隔离环境的人工接管候选。下一阶段先导入客户脱敏数据，校准队列、SLA 和排班，再接真实渠道 shadow 和 assist。生产 `automatic` 继续关闭；只有上表 Gate 具备可复核证据并由业务、安全和运维签收后，才进入新的发布版本。
