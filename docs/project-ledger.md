# 项目账本（历史记录）

> 当前唯一项目事实源已迁移至 `.project-to-act/`。本文件保留 0.5.0 阶段历史，不再更新。

## 当前目标

交付一个本地、轻量、链路完整的电商客服 Agent；由 LLM 驱动任务理解、通用路由和工具选择，由固化代码完成权限、规则、执行与后置验证。

## 身份与当前状态

- 项目 ID：`yunpai-ecommerce-agent`
- Owner：云湃一体机项目组
- 风险等级：T3，顾客会话和订单上下文可能包含个人信息
- 当前版本：`0.5.0`
- 当前阶段：LLM 驱动 ReAct 与工具接入框架
- 当前状态：结构化决策、动态工具目录、有界 ReAct、写工具幂等契约和后置验证已实现；真实平台工具尚未注册
- 下一决策点：确定首个合法平台适配器和首组真实读写工具

## 已确认边界

- 来源：`云湃电商项目调研报告_精简修订版_20260716.md`、`AI电商客服多端接入调研报告_20260718.md`。
- 具备可信权限、完整参数、明确规则和可验证工具时自动执行真实业务；只有不确定或失败时转人工。
- 首期由合法平台通道或第三方服务接入，不在本项目内绕过平台权限。
- 交付形态为单机本地一体机，SQLite 是有意选择的轻量存储。

## 决策记录

| ID | 决策 | 依据 | 风险控制 |
|---|---|---|---|
| D-001 | 使用 LLM 驱动的有界 ReAct | 需要保留模型对自然语言和工具组合的理解空间 | 通用路由、最多 4 步、结构化决策和后置验证 |
| D-002 | 使用 SQLite 混合检索 | 单机部署、156 条初始知识 | WAL、版本、来源和校验和 |
| D-003 | 自进化只更新知识 | 自动改代码风险过高 | 回归门禁、人工批准、可回滚 |
| D-004 | 确定性条件满足时自动执行写操作 | Agent 应尽可能接入真实业务 | 工具注册、权限规则、幂等、后置验证、失败转人工 |
| D-005 | 模型默认禁用 | 避免未验证配置产生外部调用 | `MODEL_ENABLED=false` 不发模型请求 |
| D-006 | context 在图外清洗 | checkpoint 会保存输入历史 | 白名单和脱敏先于 `graph.invoke` |
| D-007 | 非终态人工任务阻断留存 | 防止处理中上下文丢失 | 终态前保留会话、消息和 checkpoint |
| D-008 | 客服运行时使用 GLM 标准 Chat Completions API | Coding Plan 仅作为显式本机测试模型 | `/api/coding/` 必须设置 `MODEL_ALLOW_CODING_PLAN=true` 且固定非流式；正式配置默认使用标准端点 |
| D-009 | 进化知识按租户隔离 | 防止一个商家的修正污染其他商家 | 全局内置知识 + 租户私有进化知识 |
| D-010 | 具体业务意图不写入 LangGraph 拓扑 | 避免规则引擎替代 Agent | LLM 选择通用语义和动态工具，代码仅校验放行 |
