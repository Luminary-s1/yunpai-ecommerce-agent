## 模块信息与确认

**阶段**：`3 业务应用`　**排程方式**：`并行`

### 模块背景

```
开发智能客服模块的核心后端逻辑，交付一条可用于真实店铺接待的客服对话链路：
多轮对话状态管理、知识库检索增强的回复生成、意图识别与路由、流式输出，
以及量化的效果评测。这是四个业务模块中最复杂的一个，涉及对话状态管理、
意图分类和防幻觉约束。

本模块建立在项目功能台账既有的以下子功能之上：
· F-001 Agent 安全编排基线（LangGraph 有界 ReAct、结构化决策、动态工具目录、
  输出安全门、故障转人工、全链路审计）
· F-002 租户认证与可信会话基线（会话绑定、主体哈希、可信订单上下文能力位）
· F-003 类型化工具与动作安全框架（读写分类、参数校验、幂等字段、后置验证）
· F-004 租户知识与受控进化基线（知识版本、评测批准、可回滚）
· F-005 持久人工任务基线（合法状态机、验收条件、乐观锁、留存保护）
· F-103 统一渠道会话与可信上下文扩展（消息信封、context 白名单化）
· F-104 平台/行业/店铺/商品/进化五层知识与灰度发布
· F-105 SOP DSL 与版本化执行引擎（按意图解析 SOP 版本，Prompt 变体骨架）
· F-106 ContextBuilder 与商品/SKU 顾问（固定顺序装配、父子快照、证据 ID）
· F-113 回放、影子、灰度与发布门禁
· F-117 版本化客户 Agent 评测
· F-118 人工接管队列与 SLA
· F-119 坐席调度与智能分配
· F-120 值守排班与持久自动派单
· F-121 关联虚拟店铺与跨模块场景验收
· F-122 逐场景输入输出证据工作台
· F-123 本机顾客对话测试入口
· F-310 本地经营与客服管理后台

本模块新增登记：
· F-124 SSE 流式客服接口
· F-125 会话 Token 预算与生命周期
· F-126 意图分类与置信度路由
并扩展 F-117 的评测指标口径。

运行时模型按项目决策 D-008 统一使用 GLM 标准 Chat Completions 接口；
知识检索使用 F-104 项目内分层知识库，不依赖外部检索服务。
```

### 总体需求

```
1. 多轮对话管理（承 F-002 / F-103 / F-106，出 F-125）
   会话生命周期（创建/查询/关闭）、对话历史持久化、上下文窗口 Token 截断。
   Token 计数需与运行模型一致；截断必须保证拼入检索知识后总量不超模型
   上下文上限的 70%；历史查询支持分页；会话空闲超时自动关闭且不影响
   仍有未结人工任务的会话（决策 D-007）。

2. RAG 检索集成与流式输出（承 F-001 / F-004 / F-104 / F-106，出 F-124）
   用户消息经检索获取相关知识片段，按模板组装 Prompt 后调用模型流式生成，
   通过 SSE 推送给前端并保存到历史。断连重试必须幂等，不产生重复回复；
   模型超时与检索不可用需有明确降级，不得崩溃。

3. 意图分类与转人工兜底（承 F-003 / F-005 / F-105 / F-118 / F-119 / F-120，
   出 F-126，关联 F-107 四种人机协同接待模式）
   识别商品咨询、售后问题、投诉建议、闲聊其他四类意图，按意图选择检索范围
   与 Prompt 变体；低置信度、投诉高严重度或连续多轮回复质量不佳时触发转人工，
   并在响应中通知前端。意图与置信度需持久化供评测追溯。

4. 效果评测（承 F-113 / F-121 / F-122，扩展 F-117）
   构建 50+ 条测试用例，量化回答准确率、幻觉率、拒答率和转人工合理率，
   定位问题根因并迭代优化 Prompt 与系统参数，输出评测报告与最终配置。

约束：不得引入新的权限放行路径；不得让模型绕过 F-001 的输出安全门；
不得改变模型默认关闭的安全启动语义（决策 D-005）；
意图分类不得写入编排拓扑（决策 D-010）；
回答必须引用不可变上下文快照（决策 D-023）。
```

### 验收标准

```
【功能验收】
1. 客服 API 支持多轮对话，能基于 F-104 知识库回答商品咨询，且多轮上下文连续
   （能理解"它多少钱"中"它"的指代）
2. 流式回复逐段送达，内容引用了检索到的知识片段；SSE 断连重试后不产生
   重复内容
3. 给定超长对话历史，截断后 Token 数不超设定阈值且保留最近对话上下文
4. 会话空闲超时自动关闭，存在未结人工任务的会话不被关闭
5. 四类意图分类准确率达可用水平（≥75%）；不同意图路由到对应检索范围与
   Prompt 变体；低置信度和投诉场景能正确触发转人工提示，转人工任务进入
   F-118 队列并可被 F-120 自动派单消费，转人工字段前端可识别
6. 评测报告覆盖全部用例，四项指标均有量化结果；回答准确率 ≥75%，
   幻觉率 ≤10%
7. 对抗场景下不泄露系统提示词、不执行越权指令
8. 模型超时或检索不可用时有明确错误提示而非崩溃

【工程验收】
9. 全量测试通过且用例数增长可归因
10. 每项能力具备反证：临时移除该能力后对应测试必须失败，并记录反证过程
11. 编排拓扑节点与边数量零变化（决策 D-010 硬检查）
12. 数据库 schema 前向迁移成功且旧数据不丢
13. 既有非流式对话接口契约零变化
14. F-121 场景证据契约扩展后全部通过

【口径声明】
接入真实模型后客服类场景存在结果波动，验收以模型受控的测试套件断言为准，
真实模型实跑结果单独标注，不得为通过而移除场景登记或放宽门禁。
生产放行不豁免：真实客户脱敏标注集、真实模型基线与真实渠道仍属
F-102 / F-117 外部阻塞项。
```

### 工作包 1：客服会话管理与上下文控制

**任务名称**

```
客服会话管理与上下文控制
```

**任务内容**

```
设计并实现客服对话的数据层基础：会话生命周期管理、对话历史持久化存储、
上下文窗口 Token 截断策略。这是整个客服模块的地基，后续的回复生成 Pipeline、
意图路由和效果评测全部依赖这一层。

关联子功能：
· 承 F-002 租户认证与可信会话基线——会话绑定、主体哈希、跨租户隔离沿用其契约
· 承 F-103 统一渠道会话与可信上下文扩展——context 白名单化必须在持久化前完成
· 承 F-106 ContextBuilder——截断后的历史需进入固定顺序装配的上下文快照
· 出 F-125 会话 Token 预算与生命周期（本包新增登记）

具体工作：
1. 完善会话与消息数据模型，确保 Session 与 Message 字段满足 F-117 评测追溯需要
2. 实现会话 CRUD API：
   POST   /v1/chat/sessions               创建会话
   GET    /v1/chat/sessions/{id}          查询会话信息
   GET    /v1/chat/sessions/{id}/messages 分页查询历史消息
   DELETE /v1/chat/sessions/{id}          关闭会话
3. 实现消息持久化：每条用户消息和模型回复入库，支持按会话查询完整对话历史
4. 实现上下文窗口管理：编写 Token 计数器，实现滑动窗口截断策略——保留
   System Prompt 与最近 N 轮对话，总 Token 不超过模型上下文限制的 70%，
   留出空间给 F-104 检索知识和生成
5. 截断元信息进入 F-106 上下文快照并作为一条证据，供审计与评测复核
6. 实现会话超时清理：超过设定时长（默认 2 小时）无活动的会话自动标记为关闭
7. 编写数据模型文档与接口契约说明
```

**具体需求**

```
Token 计数需与运行模型一致（按决策 D-008 对齐 GLM 标准 Chat Completions），
不引入本地大模型或第三方 tokenizer 依赖；
截断策略必须保证拼入 F-104 检索知识片段后总 Token 不超模型上限；
历史查询需支持分页，游标非法时返回首页而非报错；
超时清理逻辑不影响活跃会话，且必须跳过存在未结 F-005 人工任务的会话
（决策 D-007）；
所有查询带租户与主体双重过滤，越权访问返回 404 而非 403，避免泄露存在性；
接口前缀与既有 OpenAPI 保持一致，不改变 F-002 既有认证契约。
```

**验收标准**

```
1. 创建会话后能发送并存储消息
2. 查询历史能按时间顺序返回完整对话记录，分页无重复无遗漏
3. Token 截断策略验证通过：给定一个超长对话历史，截断后 Token 数不超过设定
   阈值且保留最近对话上下文，具备反证
4. 截断元信息可在 F-106 上下文快照中查到
5. 会话超时自动关闭功能验证通过，带未结人工任务的会话不被关闭
6. 四个端点具备鉴权、409、422、404 测试
7. 既有对话接口与 F-002 认证行为零变化
```

**交接内容**

```

工具函数 + 超时清理逻辑 + 数据模型文档
```

### 工作包 2：知识库增强回复生成 Pipeline

**任务名称**

```
知识库增强回复生成 Pipeline
```

**任务内容**

```
实现客服回复的核心生成链路：用户消息 → 加载对话历史并截断 → 调用知识库检索
获取相关知识 → 组装完整 Prompt（系统模板 + 检索知识 + 对话历史 + 用户消息）
→ 调用模型推理（流式）→ 通过 SSE 推送给前端 → 保存回复到历史。

关联子功能：
· 承 F-001 Agent 安全编排基线——生成结果必须过既有输出安全门，不通过转人工
· 承 F-004 租户知识与受控进化基线——只检索已批准版本，进化知识按租户隔离
· 承 F-104 五层分层知识与灰度发布——检索范围含平台/行业/店铺/商品/进化层，
  会话按稳定分桶决定是否命中灰度候选版本
· 承 F-106 ContextBuilder——知识片段与商品候选带稳定证据 ID 进入上下文包
· 出 F-124 SSE 流式客服接口（本包新增登记）

具体工作：
1. 实现回复生成主流程 API，接收用户消息并返回 SSE 流
2. 集成 F-104 知识检索：将用户当前消息作为查询，获取 top-k 相关知识片段
3. 实现 Prompt 组装逻辑：填充知识片段、对话历史、用户消息变量插槽，
   确保防幻觉指令生效
4. 实现模型流式调用与 SSE 封装，事件协议覆盖
   meta / delta / citations / handoff / done / error
5. 实现幂等设计与断连重试处理
6. 实现错误处理与降级策略：检索不可用、模型超时、模型限流三条路径
7. 编写 SSE 事件协议说明文档，供前端对接
```

**具体需求**

```
SSE 协议需与项目既有流式接口规范一致；
断连重试不能产生重复回复，复用既有幂等键机制，不另建幂等设计；
模型 API 超时需有明确的前端提示；
防幻觉指令必须来自 F-001 统一的 Prompt 模板而非散落硬编码；
检索服务不可用时需有降级策略——仅基于对话历史回复并标注"当前无法引用知识库"；
流式与非流式的降级行为必须一致；非流式接口契约不变；
不得改变编排拓扑，回答必须引用 F-106 上下文快照（决策 D-010、D-023）；
error 事件后必须紧跟 done 关闭流，不得让客户端挂死；
模型未启用时不得发出任何外部请求（决策 D-005）。
```

**验收标准**

```
1. 发送用户消息后能收到流式回复，回复内容引用了 F-104 检索到的知识片段
2. 多轮对话上下文连续，能理解"它多少钱"中的"它"指代上文商品
3. SSE 断连重试后不产生重复内容，返回同一消息 ID 且历史表不新增行
4. 中途断开不留下半条回复记录
5. 模型超时或检索服务不可用时有明确错误提示而非崩溃
6. 模型未启用时端点不发出任何外部请求
7. F-001 输出安全门在流式路径下同样生效，不通过时转人工
8. 反证：流式改为一次性返回全文后，"逐段送达"断言必须失败
```

**交接内容**

```
F-124 客服回复生成 Pipeline 后端服务：检索集成 + Prompt 组装 + 模型流式调用
+ SSE 封装 + 错误处理 + 降级策略 + 事件协议说明文档
```

预计 `56`　剩余 `0`　优先级 `1`　工作类型 `开发`　每日 `4`　进度 `100%`

### 工作包 3：客服意图识别与路由逻辑

**任务名称**

```
客服意图识别与路由逻辑
```

**任务内容**

```
在回复生成 Pipeline 外层增加意图分类和路由能力：识别用户消息类型
（商品咨询/售后问题/投诉建议/闲聊其他），根据意图选择不同的检索策略和
Prompt 变体，实现低置信度转人工兜底。

关联子功能：
· 承 F-003 类型化工具与动作安全框架——高风险动作的权限门不因意图分类而放宽
· 承 F-005 持久人工任务基线——转人工任务沿用其合法状态机与乐观锁
· 承 F-105 SOP DSL 与版本化执行引擎——按意图解析 SOP 版本，作为 Prompt 变体
  的落点，会话固定版本不因灰度回滚而改变
· 承 F-118 人工接管队列与 SLA——投诉类进入既有队列并享有优先级，不新建队列
· 承 F-119 坐席调度与智能分配——转人工任务由既有资格与容量约束分配
· 承 F-120 值守排班与持久自动派单——转人工任务可被自动派单消费
· 关联 F-107 四种人机协同接待模式——意图与置信度作为模式选择的输入信号
· 出 F-126 意图分类与置信度路由（本包新增登记）

具体工作：
1. 实现意图分类器：采用混合方案——规则预筛（关键词匹配：退货/退款 → 售后，
   投诉/差评 → 投诉，多少钱/规格/参数 → 商品咨询）+ Prompt few-shot 分类
   （对规则无法判定的消息调用模型做轻量分类，输出意图标签 + 置信度）
2. 实现路由策略：
   商品咨询 → 检索商品知识范围 + 商品咨询 Prompt 变体

   闲聊     → 安全边界内简短回复

```
