# M9-R 商品流量与生命周期经营 — 任务书

> 代码域：商品/Listing/SKU 经营读模型、M5-R 证据桥接、生命周期建议和经营工作台。
> 项目负责人及里程碑收口人：**闫睿涵**。
> 工作包分工以本文为唯一来源；动态状态、工时和日期只在负责人工作台网页维护。
> 前置：[M7R_READONLY_DATA_WORKBENCH.md](M7R_READONLY_DATA_WORKBENCH.md)。

## 1. 目标

落实刘经理对 M5-R 的要求：解决平台内链接和 SKU 的经营问题，让商品更符合平台展示
和流量分配所需要的可观测条件，以获得更多曝光机会。系统不猜平台内部权重，而是复用
M5-R 的版本化 revision、指标、受控实验和黑盒分析证据，回答：

- 哪些商品当前需要保持、观察、上新、诊断或进入受控实验？
- 曝光、点击、转化、库存、价格、广告和竞品之间有哪些可复核变化？
- 选品、定价、活动、补货和清仓下一步应准备什么，哪些条件仍缺失？

对应功能：F-325。

## 2. 产品硬边界

- 存量商品默认**不改标题、不换主图**。标题错误、关键词陈旧，或曝光/点击表现差且
  数据质量满足时，系统才可提出人工审核建议；一般优先建议上新或受控实验。
- 不自动发布商品、改价、换图、报名活动、调整广告或下架清仓。
- 不宣称“平台标题权重”“主图权重”或逆向得到平台算法。
- 商品生命周期输出是带证据的建议，不是无需人工确认的事实状态。
- 精确价格动作必须考虑成本和利润准备度；M10-R 未提供完整成本时，M9-R 不给
  “一定提价 2 元”一类正式结论。

## 3. 经营读模型

每个 `store + item + SKU` 至少聚合以下只读证据：

| 证据域 | 主要字段 | 来源 |
|---|---|---|
| 商品 | 标题、主图版本、价格、属性、上架状态、商家编码/料号 | M7-R / F-305 |
| 流量 | 曝光、访客、点击、CTR、加购、转化、来源结构、数据时间 | M7-R / M5-R |
| 交易 | 下单、支付、退款、净销量可用性、销售额 | M7-R / F-306/F-307 |
| 库存 | 可售、在途、覆盖天数、缺货/积压风险 | F-303 / M10-R |
| 广告/活动 | 花费、归因成交、ROI 可用性、活动窗口 | F-308 / M7-R |
| 竞品 | 已批准同款、价格、销售区间和变化 | F-304；没有可靠来源时标 missing |
| 实验 | revision、实际窗口、uplift、区间、质量、反证、新鲜度 | F-312～F-316 |

“净销量”“广告 ROI”“利润安全价格”等不可用时必须保留不可用状态，不以支付件数、
GMV 或缺失成本替代。

## 4. 生命周期建议链

V1 提供以下建议类型，不建立自动执行路径：

```text
选品候选
  └─> 上新准备
        └─> 曝光/点击诊断
              └─> 受控实验或保持观察
                    └─> 定价/活动候选
                          └─> 补货联动
                                └─> 清仓预警或退役建议
```

代码计算时间窗、指标、质量、库存和权限等事实；模型根据用户目标和固化事实决定语义
下一步、解释证据与反证。允许动作集合与写屏障由代码控制，模型不能把建议变成平台动作。

### WP1 Listing/SKU 经营读模型与数据准备度

交付：

- `store + item + SKU` 聚合读模型、料号引用、来源、新鲜度和数据准备度。
- 曝光→点击→加购→支付→退款的漏斗事实，以及广告、库存、竞品可用性。
- 跨粒度和缺失状态检查，不复制现有领域事实表。

验收：

- 同一 item 多 SKU、同一 SKU 多 revision 和同租户多店不会串数。
- 日/月、店铺/商品、支付/退款等不同粒度不能被静默相加。
- 缺广告、竞品或退款明细时仍可显示基础流量事实，但明确阻断依赖它们的结论。
- 读模型每个值可回溯到权威服务、import manifest 和 data_as_of。

依赖：M7-R、F-303～F-308。

### WP2 M5-R 证据桥接与流量诊断

交付：

- 将商品读模型与 M5-R revision/experiment/analysis/freshness/provenance 接成同一查询。
- 曝光不足、点击不足、转化不足、缺货污染、广告/价格变更污染和证据不足的结构化诊断。
- 模型解释固化证据、反证和下一轮单变量实验建议。

验收：

- 只有满足 A/A、样本、实际窗口、控制变量和 freshness Gate 的实验才给强方向结论。
- 缺货、广告或价格变化不会被错误归因于标题/主图。
- 模型越权修改 effect、区间、样本量、Gate 或声称平台权重时整份解释被拒绝。
- 没有合格实验时返回观察/补数/实验建议，不编造 uplift。
- 任何诊断均不产生 listing、图片、广告或活动写动作。

依赖：WP1、F-312～F-316、D-037～D-040。

### WP3 商品生命周期建议、人工确认与跟踪

交付：

- 版本化建议记录：建议类型、目标对象、事实快照、假设、收益/风险、缺失项和状态。
- `draft → awaiting_review → approved/rejected → observed → closed` 的建议跟踪状态机。
- 选品、上新、保持、诊断、实验、定价候选、活动候选、补货联动、清仓预警模板。

验收：

- 建议默认 draft，只有人工可批准/拒绝；批准仍不触发平台动作。
- 对存量标题/主图的建议默认 keep/observe；只有任务书允许条件和证据满足时才显示
  “人工复核优化”，且必须保留“优先上新/实验”的替代方案。
- 缺成本时不能输出正式利润安全价格；缺竞品时不能假装有行业对标。
- 同一证据重放不重复创建建议；事实更新后旧建议标 stale，不原地改写历史。
- 语义建议由模型产生，代码只校验允许类型、必需证据、状态和写屏障。

依赖：WP1、WP2、F-304、M10-R 的成本/补货接口仅作可选增强。

### WP4 商品经营工作台与机制 Eval

交付：

- 商品列表、漏斗、流量诊断、实验、来源、建议、人工审核和后续观察页面。
- 选品/上新/存量保持/受控优化/污染/缺数据/清仓风险等冻结场景。
- 数值与结构化机制 Eval，不以文案关键词作为裁判。

验收：

- 页面能从商品/SKU 下钻到 revision、时间窗、指标、来源和建议依据。
- 显示“为什么建议”和“为什么暂不能建议”，不只给红黄绿分数。
- 查看页面不自动分析、创建实验、创建建议或修改商品；运行操作必须显式点击并审计。
- Eval 同时证明能发现真实方向和拒绝无效/污染方向，ground truth 不进入生产输入。
- 浏览器桌面与窄屏可读，console 无新增错误。

依赖：WP1～WP3、F-310、F-121/F-122。

## 6. M9-R Definition of Done

- 商品/SKU 经营读模型覆盖流量、交易、库存、广告、竞品和实验的可用/缺失状态。
- M5-R 统计事实与 AI 解释边界保持，不能输出平台内部权重或无证据因果结论。
- 生命周期建议覆盖选品到清仓，并以人工确认、可追溯和无平台写动作收口。
- 存量标题/主图默认不改的产品原则有代码边界、页面说明和反证测试。
- 独立 Eval、浏览器、租户/店铺隔离和完整回归通过；每包由独立验收人签署。

## 7. 实现纪律

- M5-R 的 `traffic_analysis_runs`、freshness 和 provenance 是权威证据，不另建简化统计旁路。
- 关键词、标题特征、健康分数和生命周期信号不得替模型决定用户意图或语义下一步。
- 状态机、数据质量、样本量、来源、新鲜度、允许动作和人工确认属于确定性安全边界。
- 如需 schema，实施前按当时 main 的 `CONTRIBUTING.md` 占号并检查所有 refs；本文不预占。
- 测试断言本包建议类型和安全边界的成员关系，不冻结全局模块/场景/状态数量。
