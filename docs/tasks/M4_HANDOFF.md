## 2. 你要交付什么

工作包预计 18 小时。四项，**按顺序做**：

| 顺序 | 内容 | 说明 |
|---:|---|---|
| 1 | 流式输出端到端实跑证据 | 真跑一遍 SSE，留可复现的输入输出 |
| 2 | 新增场景 D17 多轮指代 | 纳入 simulation-evidence-v1 契约 |

- **第 3 项要等模块负责人的 WP3 做到置信度阈值转人工**。那部分现在 55%，
  已完成的是四分类枚举、关键词规则表、独立轻量分类调用；**还没做**的是
  置信度阈值路由、阈值可配置、置信度持久化。D18 场景要断言"低置信度转人工"，
  这个能力不落地就没法写。**开工前先在群里确认 WP3 的进度**
- **第 1、2 项不依赖任何人**，可以立刻开始
- **第 4 项放最后**，它要汇总前三项的产出

## 3. 这个模块不是从零开始

M4 的会话管理与回复生成两个包已经 100% 完成。下面这些**已经有了**：

- 多轮对话可用，能基于知识库回答商品咨询

  （meta / delta / citations / handoff / done / error）

- 虚拟店铺跨模块场景验收框架 **simulation-evidence-v1，当前 16 项**
- 本机顾客直测入口（`/admin` 智能客服页，无需客户端密钥）
- 客服管理后台：会话回放、人工任务、评测、场景验收、审计

**动手前先读 `docs/tasks/PROGRESS.md` 的 M4 一节**，勾上的是已实现。
你要补的是那四个没勾的。

### 关于 D17 / D18 两个场景

现有 16 个场景的写法就是模板，照着加第 17、18 个。要点：

- 场景断言必须**确定性复现**，不能依赖模型每次输出的具体措辞
- D17 多轮指代：验证"它多少钱"这类指代能从预算内的历史里恢复出商品候选
- D18 意图路由与低置信度转人工：验证低置信度时确实走了转人工，而不是硬答
- 场景数据用显式虚拟标记，不混进真实经营数据（D-033）

## 4. 硬约束

### D-023 回答必须引用不可变上下文快照

不得绕过 `ContextBuilder` 取数。你做端到端验证时如果发现某条链路绕过了它，
这是缺陷，要报，不要在场景里将就过去。

### D-033 评测与模拟会话不污染真实数据

评测与模拟会话落 `evaluation` / `simulation` 来源，不写进 `operational`。
你的实跑证据同理。

### D-005 模型开关

`MODEL_ENABLED=false` 时不得发出任何模型请求。做流式实跑证据时会开模型，
注意别把这条测挂了。

### 其他

- 不新增第三方依赖，需要先提出来
- 场景证据契约（simulation-evidence-v1）是共享契约，改它之前先说一声
- 当前 `SCHEMA_VERSION = 25`，你这个包不该动表；真要动先在群里占号
