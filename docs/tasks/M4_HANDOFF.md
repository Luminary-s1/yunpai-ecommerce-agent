## 2. 胡磊：客服模块效果评测与调优（16h）

### 这一包不是从零开始

评测底座已经有了，**不要重复造**：

- 标注集不可变版本、冻结、数据集 SHA-256 哈希
- 隔离数据库快照中运行真实多轮 Agent，主库零污染
- 跨版本回归对比、门禁阈值与发布关联
- 现有指标：通过率、意图准确率、转人工召回、证据覆盖、严重错误、回归率
- 断言维度：`expected_intent`、`expected_requires_human`、`require_sources`、
  `required/forbidden_answer_terms`、`max_risk_level`
- 对抗模式基线（Prompt 注入、越权数据、禁止输出）
- 离线评测 20 例

主实现在 `src/ecommerce_agent/evaluation.py`，离线用例在
`src/ecommerce_agent/evals.py`。

### 你要补的四块

**① 用例集扩到 50+ 条**

`evals.py` 现在是三个扁平列表：`RETRIEVAL_CASES` 12 条、`SAFETY_CASES` 5 条、
`PRECHECK_CASES` 3 条。要扩到：商品 15 / 售后 12 / 投诉 8 / 闲聊 5 / 对抗 10+。

写用例不需要架构知识，但要先把知识库和 `SYSTEM_PROMPT` 的八条硬边界读一遍，
否则写出来的期望值站不住。

**② 四个指标：回答准确率、幻觉率、拒答率、转人工合理率**

按 M4 口径实现，接进既有的门禁阈值机制。

**③ 判定标准文档化**——什么算"准确"、什么算"幻觉"。

⚠️ **这一项和上一项的口径要和模块负责人一起定，不要单方面拍板。** 指标口径直接
决定发布门禁能不能过，定松了门禁失效，定严了发不出去。你负责实现和文档化，
口径本身要他确认。

**④ 自动化评测脚本 + 调优记录与最终参数配置文档**

### 验收标准

1. 用例集达到 50+ 条且分类配比符合要求
2. 四个指标可计算、可复现，接入门禁阈值
3. 判定标准有书面定义，且经模块负责人确认
4. 评测脚本可一键跑，输出可归档
5. 调优记录能说明每次参数变化带来的指标变化
6. 反证：把某条用例的期望值改错，对应指标必须下降

## 3. 缪海南：客服对话引擎端到端联调与交付（18h）

### 这一包不是从零开始

M4 的会话管理与回复生成两个包已经 100% 完成。**已经有了**：

- 多轮对话可用，能基于知识库回答商品咨询
- SSE 流式输出接口 `POST /v1/chat/stream`，事件协议
  （meta / delta / citations / handoff / done / error）
- 会话生命周期、Token 预算与滑动窗口截断
- 幂等设计（Idempotency-Key + `agent_invocations` 表，断连重放不重复回复）
- 虚拟店铺跨模块场景验收框架 **simulation-evidence-v1，当前 16 项**
- 本机顾客直测入口（`/admin` 智能客服页，无需客户端密钥）
- 客服管理后台：会话回放、人工任务、评测、场景验收、审计

### 四项交付，按顺序做

| 顺序 | 内容 | 依赖 |
|---:|---|---|
| 1 | 流式输出端到端实跑证据 | 无，现在就能做 |
| 2 | 新增场景 D17 多轮指代 | 无 |
| 3 | 新增场景 D18 意图路由与低置信度转人工 | **等模块负责人的意图路由** |
| 4 | 交付文档 + 四份台账同步 | 前三项 |

**第 3 项要等**：意图路由那个包现在 43%，已完成四分类枚举、关键词规则表、
独立轻量分类调用；**还没做**置信度阈值路由、阈值可配置、置信度持久化。
D18 场景要断言"低置信度转人工"，这个能力不落地就没法写。**开工前先在群里
确认进度。** 这期间先做第 1、2 项，或者推进你在 M5 / M6 的活。

### 关于 D17 / D18

现有 16 个场景的写法就是模板，照着加第 17、18 个：

- 场景断言必须**确定性复现**，不能依赖模型每次输出的具体措辞
- D17 多轮指代：验证"它多少钱"这类指代能从预算内的历史里恢复出商品候选
- D18：验证低置信度时确实走了转人工，而不是硬答

### 验收角色的纪律

- **数值与行为类结论要人工核对**，不能只看接口返回码或测试是否变绿
- 发现的问题走缺陷清单回给模块负责人，**不要自己顺手改开发包的代码**——
  那会破坏开发与测试分离
- 你在 M6 开发、在 M5 开发，只有 M4 是验收角色，别串了

## 4. 硬约束（两位都适用）

### D-023 回答必须引用不可变上下文快照

不得绕过 `ContextBuilder` 取数。端到端验证时如果发现某条链路绕过了它，
这是缺陷，要报，不要在场景里将就过去。

### D-033 评测与模拟会话不污染真实数据

评测与模拟会话落 `evaluation` / `simulation` 来源，不写进 `operational`。
实跑证据同理，测试数据打显式虚拟标记。

### D-005 模型开关

`MODEL_ENABLED=false` 时不得发出任何模型请求。做流式实跑证据、跑评测时会开
模型，注意别把这条测挂了。

### D-010 业务意图不写入编排拓扑

不得新增按意图分支的节点或边。

### 其他

- 不新增第三方依赖，需要先提出来
- 场景证据契约（simulation-evidence-v1）是共享契约，改它之前先说一声
- 当前 `SCHEMA_VERSION = 25`，这两个包都不该动表；真要动先在群里占号
