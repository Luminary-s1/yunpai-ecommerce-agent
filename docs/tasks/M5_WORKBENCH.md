## 模块信息与确认

**阶段**：`3 业务应用`　**排程方式**：`并行`

### 模块背景

```
开发运营辅助后端：运营数据解析接口、营销文案生成引擎、运营分析报告生成。
将电商运营数据通过模型转化为可读的文案和分析洞察。

本模块的定位是"代码负责事实，模型负责表达"——销售、投放、转化率、客单价和
ROI 等所有数值由代码计算，模型只负责文字解读与文案撰写，不能修改统计值。
所有生成的文案在人工审核前不可发布。

本模块建立在项目功能台账既有的以下子功能之上：
· F-301 全域业务模块注册表（模块声明职责、边界、状态与 Agent 工具，
  API 状态不虚报）
· F-302 统一 Connector SDK 与虚拟接口（能力声明、连接检查、拉取、动作、
  读回验证同一契约）
· F-305 商品与渠道 SKU 事实模块（来源时间、载荷哈希、防旧覆盖、幂等、冲突）
· F-307 指标语义与经营诊断（指标公式代码化，模型只选择严格 QuerySpec）
· F-308 营销与内容模块（版本化广告日指标、ROAS/CTR 诊断、
  内容草稿有限事实检查）
· F-121 关联虚拟店铺与跨模块场景验收
· F-122 逐场景输入输出证据工作台
· F-310 本地经营与客服管理后台

本模块新增登记：
· F-311 运营辅助与文案生成模块（注册表模块键 ops_assistant）

模块复用项目统一的租户隔离、来源版本与载荷哈希、幂等写入、审计与管理后台底座；
运行时模型按项目决策 D-008 统一使用 GLM 标准 Chat Completions 接口。
```

### 总体需求

```
1. 运营数据接口（承 F-302 / F-305，出 F-311）
   支持 CSV / JSON 文件上传和表单手动录入两种方式，解析商品销量、访客数、
   转化率、客单价等核心运营指标，执行格式校验和数值合法性检查，
   结构化持久化并提供查询 API 供下游报告模块消费。
   需兼容常见电商平台（淘宝 / 京东 / 抖音商家后台）的导出模板。
   写入语义沿用 F-305 的来源时间与载荷哈希版本契约（决策 D-014）：
   旧版本拒绝、同版本同载荷幂等、同版本不同载荷冲突。

2. 营销文案生成（承 F-308）
   输入商品信息（名称、卖点、目标人群）→ 选择文案风格 → 组装 Prompt 模板 →
   调用模型生成 → 返回多版本文案供选择。支持单次和批量生成，
   每种风格有独立 Prompt 变体，文案长度可控，生成结果支持编辑后重新生成。
   沿用 F-308 的内容草稿有限事实检查与"发布前必须审批"边界。

3. 运营分析报告（承 F-307）
   消费结构化运营数据，计算销售趋势环比与同比、流量转化漏斗、客单价变化，
   基于可配置阈值检测异常指标并触发预警，调用模型生成文字版运营洞察和
   优化建议，输出结构化报告并支持导出。
   所有统计值按 F-307 的口径由代码计算，模型不得修改。

4. 模块登记与场景验收（承 F-301 / F-121 / F-122 / F-310）
   在业务模块注册表中登记 ops_assistant，状态与实际能力一致；
   在虚拟店铺场景中新增覆盖场景，纳入 simulation-evidence-v1 契约；
   后台提供可直接操作上述能力的页面。

约束：所有统计值由代码计算，模型不得修改；模型不可用时逐条降级为确定性模板
并显式标记生成方式；报告仅给出数据解读与建议，不执行预算、价格、库存或
发布操作；虚拟验收数据集与真实运营数据集分离，不混算（决策 D-033）。
```

### 验收标准

```
【功能验收】
1. 上传符合格式的 CSV / JSON 文件后能正确解析并返回结构化数据
2. 上传格式异常的文件时返回明确的错误定位信息（哪一行、哪个字段出错）
3. 表单手动录入功能可用且数据正确入库
4. 数据查询 API 返回正确的历史运营数据，支持按日期范围与商品维度查询
5. 至少通过 3 种不同电商平台导出格式的解析验证
6. 输入商品信息后能生成多种风格的营销文案，内容质量和多样性经验证可用
7. 文案长度可控，支持编辑后重新生成
8. 输入一周以上的运营数据后能生成包含数据概览、趋势分析、异常预警、
   优化建议的完整报告
9. 趋势分析中的环比与同比数值计算正确（人工核对）
10. 异常预警能正确触发（输入异常数据时能识别并标注）
11. 优化建议引用了具体数据指标而非空泛表述
12. 报告导出为文本文件功能可用

【工程验收】
13. 全量测试通过且用例数增长可归因
14. 每项能力具备反证：临时移除后对应测试必须失败
15. 数据写入按租户、数据集、日期、渠道幂等，重复导入不产生重复记录
16. 跨租户数据隔离，其他租户无数据可读
17. 模型调用失败时逐条降级且返回值显式标记生成方式，混合结果不被误标为
    纯模型生成
18. 报告读取不受列表接口展示上限影响，大数据集不被静默截断
19. F-301 注册表中 ops_assistant 状态与实际能力一致，登记为 available 的模块
    必须有 F-121 通过场景（登记即需覆盖，不得靠移除登记规避门禁）

【边界声明】
所有候选文案默认不可发布，发布前必须人工审核卖点、价格和促销主张；
虚拟验收数据集与真实运营数据集分离，不混算；
开发数据库与截图仅用于本地验收，不构成生产经营结论。
```

**任务名称**

```
运营内容与数据服务验收测试
```

**任务内容**

```
独立验证运营文案生成、数据接口、分析结果和上传服务的正确性、边界与可用性。

关联子功能：
· 承 F-121 关联虚拟店铺与跨模块场景验收——用虚拟店铺数据包作为测试样本来源
· 承 F-122 逐场景输入输出证据工作台——测试结论需能对应到固定输入与预期

覆盖范围：
1. 数据上传解析的正常与异常路径（格式错误、字段缺失、数值越界、编码问题）
2. 表单录入与幂等重放行为
3. 多风格文案生成的内容质量与多样性
4. 模型不可用时的降级行为与生成方式标记
5. 分析报告的数值正确性（环比、同比、ROI 人工核对）
6. 异常预警的触发与漏报
7. 跨租户数据隔离
8. 大数据集报告不被列表上限静默截断
```

**具体需求**

```
基于真实或脱敏样例执行功能、异常和质量测试；
不得由同一开发承接人自行完成测试；
数值类结论需人工核对而非仅看接口返回码；
需覆盖至少 3 种电商平台导出格式的样例文件；
测试数据需使用显式虚拟标记，不得混入真实运营数据集。

```

### 工作包 4：营销文案生成引擎开发

**任务名称**

```
营销文案生成引擎开发
```

**任务内容**

```
实现文案生成 Pipeline：用户输入商品信息（名称、卖点、目标人群）→ 选择文案风格
（小红书种草 / 直播话术 / 详情页文案 / 朋友圈推广）→ 组装 Prompt 模板
（填充商品变量）→ 调用模型生成 → 返回多版本文案供选择。支持单次生成和批量生成。

关联子功能：
· 承 F-308 营销与内容模块——内容草稿的有限事实检查、风险词标记与
  "发布前必须审批"边界沿用其口径，不新建一套发布规则
· 承 F-305 商品与渠道 SKU 事实模块——商品变量取自版本化商品事实，
  不接受调用方自报的价格与卖点
· 出 F-311 运营辅助与文案生成模块

具体工作：
1. 扩充并对齐文案风格枚举，覆盖任务书要求的四种电商投放场景
   （小红书种草 / 直播话术 / 详情页文案 / 朋友圈推广）。现有五种是语气风格，
   四种是投放场景，需新增而非改名
2. 为每种风格编写独立的 Prompt 变体，而非同一模板换风格描述词
3. 实现文案长度控制（短 / 中 / 长），输出字数区间可验证
4. 支持前端编辑修改后基于修改内容重新生成，而非拿原始输入重跑

模型不可用时的逐条模板降级与生成方式标记、风险词标记、"发布前必须人工审核"
边界、批量上限保护与后台文案工作区已实现，本包保持不破坏。
```

**具体需求**

```
每种风格需有独立的 Prompt 变体；
生成结果需支持前端编辑修改后重新生成；
文案长度需可控（短 / 中 / 长）；
批量生成需有上限保护；
模型单次调用失败时按条降级为确定性模板，返回值显式标记 model / template /
template_fallback，混合结果不得被误标为纯模型生成；
所有候选文案默认不可发布，沿用 F-308 的审批边界；
文案中出现的价格与卖点必须来自 F-305 版本化商品事实。
```

```
1. 输入商品信息后能生成多种风格的营销文案，内容质量和多样性经验证可用

3. 长度控制生效，短 / 中 / 长输出字数区间可验证
4. 编辑后重新生成能基于修改内容而非原始输入
5. 模型失败时降级可用且标记正确，混合批次不被误标
6. 所有候选文案 publication_allowed 为 false
7. 反证：移除风格变体后风格特征断言必须失败
```

**交接内容**

```
文案生成后端服务 + 生成 API + 四种风格 Prompt 变体 + 长度控制逻辑
+ 后台文案工作区

环比与同比、流量转化漏斗、客单价变化），检测异常指标（基于阈值规则，
如转化率骤降超 30% 触发预警），将数据摘要与分析指令组装后调用模型生成文字版
运营洞察和优化建议，最终输出结构化运营报告（数据概览 → 趋势分析 → 异常预警
→ 优化建议），支持报告导出为文本格式。

关联子功能：
· 承 F-307 指标语义与经营诊断——指标公式代码化，模型只消费计算结果，
  报告需带定义版本、数据水位与证据数量
· 承 F-308 营销与内容模块——投放相关诊断口径与其 ROAS/CTR 诊断保持一致
· 承 F-310 本地经营与客服管理后台——报告在后台可直接生成与查看
· 出 F-311 运营辅助与文案生成模块

具体工作（本包整包交给谢良璇承接，交接说明见 `docs/tasks/M5_HANDOFF.md`）：
1. 环比计算（本周 vs 上周，4h）——现有 `_trends` 算的是区间对半切的前后半段，
   不是环比。需按自然周分组；跨月边界按日期不按月切；数据不足两个完整周时
   明确标注不可比，不返回 0 也不抛异常
2. 同比计算（本月 vs 上月，4h）——按自然月分组。两月天数不等时需带可比性标记
   或按日均归一，选哪种在提交信息里说明理由
3. 异常检测阈值抽取到配置文件（4h）——现阈值硬编码在 `_trends` 与 `_findings`
   里。抽到 JSON 配置，路径可用环境变量覆盖，内置默认值兜底；配置缺失或损坏时
   用默认值继续并在 `data_quality` 标注，不得让报告接口失败。至少覆盖
   转化率下降 > 30%、销量环比下降 > 50%
4. 报告结构补齐独立的异常预警章节（4h）——新增 `alerts` 键，每条带规则码、
   触发阈值、实际值、严重度；`findings` 保留不动；正常数据下返回空数组不缺键
5. 优化建议强制绑定具体数值指标（4h）——目前 `sales_declining`、
   `spend_up_sales_flat` 等建议无数值。数值只能取自代码算出的 `totals` /
   `trends`，不得由模型生成或回填
6. 报告导出为文本格式（4h）——导出内容必须取自 `analysis_report` 的返回结构，
   不在导出侧二次计算

边界：只新增返回键，不改 `trends` / `findings` / `summary` 的既有字段结构，
既有测试依赖它们。报告读取不复用列表上限一项已实现，本包保持不破坏。
```

**具体需求**

```
报告需遵循固定结构模板（摘要 → 核心指标 → 趋势分析 → 异常预警 → 优化建议）；
趋势分析需计算环比（本周 vs 上周）和同比（本月 vs 上月）变化率；
异常预警基于可配置的阈值规则（如转化率下降超 30%、销量环比下降超 50%），
阈值需写入配置文件可调整；
优化建议必须引用具体数据（如"本周转化率为 2.3%，较上周下降 35%，建议检查
商品详情页主图是否更换"），不能是空泛的通用建议；
所有统计值按 F-307 口径由代码计算，模型只负责文字解读；
报告导出需支持纯文本格式，本阶段不要求 PDF；
报告读取不得复用列表接口的展示上限。
```

**验收标准**

```
1. 输入一周以上的运营数据后能生成包含数据概览、趋势分析、异常预警、
   优化建议的完整报告
2. 趋势分析中的环比与同比数值计算正确（人工核对）
3. 异常预警能正确触发（输入异常数据时能识别并标注）
4. 优化建议引用了具体数据指标而非空泛表述
5. 报告导出为文本文件功能可用
6. 501 行以上数据集的报告合计正确，不被列表上限静默截断
7. 反证：调整阈值配置后预警触发行为必须相应变化
8. 反证：移除环比计算后环比数值断言必须失败
9. 反证：移除建议的数值绑定后，"建议必含具体数字"的断言必须失败
```
