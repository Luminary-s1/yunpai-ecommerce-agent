## 模块信息与确认

**阶段**：`3 业务应用`　**排程方式**：`并行`

### 模块背景

```
开发运营辅助后端：运营数据解析接口、营销文案生成引擎、运营分析报告生成。
将电商运营数据通过模型转化为可读的文案和分析洞察。

本模块的定位是"代码负责事实，模型负责表达"——销售、投放、转化率、客单价和
ROI 等所有数值由代码计算，模型只负责文字解读与文案撰写，不能修改统计值。
所有生成的文案在人工审核前不可发布。

本模块建立在项目功能台账既有的以下子功能之上：
· F-301 全域业务模块注册表（模块声明职责、边界、状态与 Agent 工具，
  API 状态不虚报）
· F-302 统一 Connector SDK 与虚拟接口（能力声明、连接检查、拉取、动作、
  读回验证同一契约）
· F-305 商品与渠道 SKU 事实模块（来源时间、载荷哈希、防旧覆盖、幂等、冲突）
· F-307 指标语义与经营诊断（指标公式代码化，模型只选择严格 QuerySpec）
· F-308 营销与内容模块（版本化广告日指标、ROAS/CTR 诊断、
  内容草稿有限事实检查）
· F-121 关联虚拟店铺与跨模块场景验收
· F-122 逐场景输入输出证据工作台
· F-310 本地经营与客服管理后台

本模块新增登记：
· F-311 运营辅助与文案生成模块（注册表模块键 ops_assistant）

模块复用项目统一的租户隔离、来源版本与载荷哈希、幂等写入、审计与管理后台底座；
运行时模型按项目决策 D-008 统一使用 GLM 标准 Chat Completions 接口。
```

### 总体需求

```
1. 运营数据接口（承 F-302 / F-305，出 F-311）
   支持 CSV / JSON 文件上传和表单手动录入两种方式，解析商品销量、访客数、
   转化率、客单价等核心运营指标，执行格式校验和数值合法性检查，
   结构化持久化并提供查询 API 供下游报告模块消费。
   需兼容常见电商平台（淘宝 / 京东 / 抖音商家后台）的导出模板。
   写入语义沿用 F-305 的来源时间与载荷哈希版本契约（决策 D-014）：
   旧版本拒绝、同版本同载荷幂等、同版本不同载荷冲突。

2. 营销文案生成（承 F-308）
   输入商品信息（名称、卖点、目标人群）→ 选择文案风格 → 组装 Prompt 模板 →
   调用模型生成 → 返回多版本文案供选择。支持单次和批量生成，
   每种风格有独立 Prompt 变体，文案长度可控，生成结果支持编辑后重新生成。
   沿用 F-308 的内容草稿有限事实检查与"发布前必须审批"边界。

3. 运营分析报告（承 F-307）
   消费结构化运营数据，计算销售趋势环比与同比、流量转化漏斗、客单价变化，
   基于可配置阈值检测异常指标并触发预警，调用模型生成文字版运营洞察和
   优化建议，输出结构化报告并支持导出。
   所有统计值按 F-307 的口径由代码计算，模型不得修改。

4. 模块登记与场景验收（承 F-301 / F-121 / F-122 / F-310）
   在业务模块注册表中登记 ops_assistant，状态与实际能力一致；
   在虚拟店铺场景中新增覆盖场景，纳入 simulation-evidence-v1 契约；
   后台提供可直接操作上述能力的页面。

约束：所有统计值由代码计算，模型不得修改；模型不可用时逐条降级为确定性模板
并显式标记生成方式；报告仅给出数据解读与建议，不执行预算、价格、库存或
发布操作；虚拟验收数据集与真实运营数据集分离，不混算（决策 D-033）。
```

### 验收标准

```
【功能验收】
1. 上传符合格式的 CSV / JSON 文件后能正确解析并返回结构化数据
2. 上传格式异常的文件时返回明确的错误定位信息（哪一行、哪个字段出错）
3. 表单手动录入功能可用且数据正确入库
4. 数据查询 API 返回正确的历史运营数据，支持按日期范围与商品维度查询
5. 至少通过 3 种不同电商平台导出格式的解析验证
6. 输入商品信息后能生成多种风格的营销文案，内容质量和多样性经验证可用
7. 文案长度可控，支持编辑后重新生成
8. 输入一周以上的运营数据后能生成包含数据概览、趋势分析、异常预警、
   优化建议的完整报告
9. 趋势分析中的环比与同比数值计算正确（人工核对）
10. 异常预警能正确触发（输入异常数据时能识别并标注）
11. 优化建议引用了具体数据指标而非空泛表述
12. 报告导出为文本文件功能可用

【工程验收】
13. 全量测试通过且用例数增长可归因
14. 每项能力具备反证：临时移除后对应测试必须失败
15. 数据写入按租户、数据集、日期、渠道幂等，重复导入不产生重复记录
16. 跨租户数据隔离，其他租户无数据可读
17. 模型调用失败时逐条降级且返回值显式标记生成方式，混合结果不被误标为
    纯模型生成
18. 报告读取不受列表接口展示上限影响，大数据集不被静默截断
19. F-301 注册表中 ops_assistant 状态与实际能力一致，登记为 available 的模块
    必须有 F-121 通过场景（登记即需覆盖，不得靠移除登记规避门禁）

【边界声明】
所有候选文案默认不可发布，发布前必须人工审核卖点、价格和促销主张；
虚拟验收数据集与真实运营数据集分离，不混算；
开发数据库与截图仅用于本地验收，不构成生产经营结论。
```

### 工作包 5：运营分析与报告生成开发

**任务名称**

```
运营分析与报告生成开发
```

**任务内容**

```
开发运营分析报告生成服务：消费结构化运营数据，计算关键分析指标（销售趋势
环比与同比、流量转化漏斗、客单价变化），检测异常指标（基于阈值规则，
如转化率骤降超 30% 触发预警），将数据摘要与分析指令组装后调用模型生成文字版
运营洞察和优化建议，最终输出结构化运营报告（数据概览 → 趋势分析 → 异常预警
→ 优化建议），支持报告导出为文本格式。

关联子功能：
· 承 F-307 指标语义与经营诊断——指标公式代码化，模型只消费计算结果，
  报告需带定义版本、数据水位与证据数量
· 承 F-308 营销与内容模块——投放相关诊断口径与其 ROAS/CTR 诊断保持一致
· 承 F-310 本地经营与客服管理后台——报告在后台可直接生成与查看
· 出 F-311 运营辅助与文案生成模块

具体工作：
1. 实现环比计算（本周 vs 上周）与同比计算（本月 vs 上月）
2. 异常检测阈值抽取到配置文件，支持调整
3. 报告结构补齐独立的异常预警章节
4. 优化建议强制绑定具体数值指标
5. 实现报告导出为文本格式
6. 报告读取不复用列表接口展示上限，大数据集不被静默截断
7. 新增虚拟店铺场景覆盖本模块，纳入 F-122 场景证据契约
```

**具体需求**

```
报告需遵循固定结构模板（摘要 → 核心指标 → 趋势分析 → 异常预警 → 优化建议）；
趋势分析需计算环比（本周 vs 上周）和同比（本月 vs 上月）变化率；
异常预警基于可配置的阈值规则（如转化率下降超 30%、销量环比下降超 50%），
阈值需写入配置文件可调整；
优化建议必须引用具体数据（如"本周转化率为 2.3%，较上周下降 35%，建议检查
商品详情页主图是否更换"），不能是空泛的通用建议；
所有统计值按 F-307 口径由代码计算，模型只负责文字解读；
报告导出需支持纯文本格式，本阶段不要求 PDF；
报告读取不得复用列表接口的展示上限。
```
