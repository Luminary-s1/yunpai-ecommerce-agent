## 模块信息与确认

**阶段**：`3 业务应用`　**排程方式**：`并行`

### 模块背景

```
开发竞品分析子系统：竞品数据的录入与结构化管理，以及利用模型生成竞品对比
分析报告。这是四个业务模块中相对独立的一个。

本模块的核心约束是"竞品事实必须可追溯、可解释、经人工确认"（项目决策 D-025）：
上游 SKU 对应关系可能把不同容量、套装或型号误判为同款，价格和口碑若直接进入
模型会形成不可追溯的错误建议。因此竞品数据先经过可解释的同款候选评分与人工
裁决，批准后其价格、卖点与脱敏聚合口碑才允许进入分析与 Agent 建议。

本模块建立在项目功能台账既有的以下子功能之上：
· F-301 全域业务模块注册表（模块声明职责、边界、状态与 Agent 工具）
· F-302 统一 Connector SDK 与虚拟接口（能力声明、拉取、动作、读回验证）
· F-304 竞品可信实体、内容证据与监控（可解释同款候选、版本化人工裁决、
  价格与卖点与脱敏聚合口碑、版本化阈值、持久告警、幂等重评、监控 worker）
· F-305 商品与渠道 SKU 事实模块（自有商品作为对比基准的事实来源）
· F-307 指标语义与经营诊断（可量化维度的计算口径）
· F-121 关联虚拟店铺与跨模块场景验收
· F-122 逐场景输入输出证据工作台
· F-310 本地经营与客服管理后台

本模块新增登记：
· F-312 竞品对比分析与报告生成引擎
并扩展 F-304 的数据录入通道与筛选维度。

不保存评论者身份或原始评论内容，不自动改价，不自动调整投放。
```

### 总体需求

```
1. 竞品数据结构化管理（承 F-304 / F-305，扩展 F-304）
   定义竞品数据 Schema，包含标准维度（商品名称、价格、核心卖点、用户评价摘要、
   评分、销量排名）并支持自定义分析维度扩展。提供完整 CRUD、手动表单录入和
   CSV 批量导入（含字段格式校验、数据去重、异常行报错），支持按品类、品牌、
   价格区间、评分范围等多维组合筛选查询，竞品数据可关联 F-305 自有商品作为
   对比基准。去重沿用 F-304 的来源版本与载荷哈希语义（决策 D-014）。

2. 竞品对比分析引擎（承 F-304 / F-307，出 F-312）
   输入自有商品数据与竞品数据列表，执行多维度对比：价格区间对比（纯数据计算，
   按 F-307 口径）、核心卖点差异分析（模型推理）、用户评价情感倾向对比
   （模型推断或规则匹配）、市场定位建议（模型推理）。使用竞品分析 Prompt 模板
   组装上下文，支持用户自定义选择分析维度。
   分析输入只允许使用 F-304 中经人工批准的同款匹配数据（决策 D-025）。

3. 报告呈现与导出（出 F-312）
   报告结构化呈现——先对比表格（价格、评分、卖点一目了然），再文字解读
   （差异分析 + 建议），支持导出为文本或 Markdown 格式。

4. 模块登记与场景验收（承 F-301 / F-121 / F-122 / F-310）
   注册表中 competitive 模块状态与实际能力一致；新增覆盖场景纳入
   simulation-evidence-v1 契约；后台提供可直接操作的分析与报告页面。

约束：可量化维度必须有数值计算支撑，不能是空泛表述；
分析只输出建议，不执行改价、下架或投放动作；
未经人工批准的同款匹配不得进入分析结论；
不保存评论者身份或原始评论内容。
```

7. 报告内容有数据支撑且逻辑清晰，价格等可量化维度有数值计算

13. 跨租户数据隔离

15. F-301 注册表中 competitive 状态与实际能力一致，且有 F-121 场景覆盖

【边界声明】

不自动改价、不自动调整投放；

不构成生产结论。

### 工作包 3：竞品数据模型定义与结构化管理服务

**任务名称**

```
竞品数据模型定义与结构化管理服务
```

**任务内容**

```
定义竞品数据 Schema，包含标准维度并支持自定义分析维度扩展。开发竞品数据的
完整 CRUD API，支持手动表单录入和 CSV 批量导入（含字段格式校验、数据去重、
异常行报错提示）。实现按品类、品牌、价格区间等多维度筛选和查询能力，
数据持久化到数据库。

关联子功能：
· 承 F-304 竞品可信实体、内容证据与监控——CRUD 与裁决状态机沿用其乐观锁与
  不可变历史语义
· 承 F-305 商品与渠道 SKU 事实模块——对比基准关联使用其 SKU 与版本口径
· 承 F-310 本地经营与客服管理后台——录入、筛选与裁决在后台可直接操作

本包是 M6 数据层的唯一归口：**CSV 批量导入、列名映射与数值清洗、字段级错误
提示、自定义维度的定义与扩展、四种维度的筛选查询，实现全部在本包**。
工作包 2 只做分析侧取数适配，直接调用本包的接口，不重复实现。

具体工作：
1. CSV 批量导入接口：列名映射、数值清洗、字段级错误提示、异常行跳过
2. 多维组合筛选：品类、品牌、价格区间、评分范围（评分筛归一化值，不筛原值）
3. 自定义维度的定义、扩展与参与查询
4. 竞品与自有商品的对比基准关联能力完善
5. 校验规则与错误契约固化
6. 后台页面完成导入、筛选与裁决操作
7. 在 F-301 注册表中核对 competitive 模块状态与实际能力一致
```

**具体需求**

```
1）数据 Schema 需包含标准字段并支持自定义维度扩展，以适应不同品类的分析需求；
2）CSV 导入需处理常见电商平台数据导出格式（列名映射、数值清洗），
   异常行需标记并跳过，不能整批失败；
3）需提供按品类、品牌、价格区间、评分范围等多维组合筛选查询。
   **评分口径：各平台评分制式不同（五分制、十分制、百分制），因此原值与制式
   分开存（`rating_value` + `rating_scale`），派生的归一化评分由代码计算。
   「按评分范围筛选」必须筛归一化值，不得筛原值**——否则五分制的 4.5 分和
   十分制的 4.5 分会被当成同一档，跨平台筛选没有意义。派生值按项目
   "代码算数"的原则由代码现算，不额外落一份可能与原值漂移的冗余列；
4）竞品数据需关联 F-305 自有商品（设定对比基准商品）；
5）导入异常需返回明确的字段级错误提示；
6）跨租户数据不可互读；
7）状态变更使用乐观锁，并发裁决冲突可识别。
```

**验收标准**

```
1. 能通过 API 或 CSV 录入竞品商品数据并持久化存储
2. 支持按品类 / 品牌 / 价格区间 / 评分范围筛选查询；评分筛选走归一化值，
   用五分制与十分制两种来源各造一条样本，确认同一实际水平能被同一区间筛出
3. CSV 批量导入含格式校验和去重，异常行有明确的字段级报错
4. 自定义维度可扩展并参与查询
5. 竞品可关联自有基准商品
6. 跨租户隔离验证通过
7. 并发裁决产生乐观锁冲突而非静默覆盖
```

**交接内容**

```
竞品数据管理服务（数据模型定义 + CRUD API + CSV 批量导入接口
+ 多维筛选查询接口 + 数据校验逻辑）+ 后台操作页面
```

### 工作包 4：竞品对比分析引擎开发

**任务名称**

```
竞品对比分析引擎开发
```

**任务内容**

```
利用模型对自有商品与竞品进行多维度对比分析。输入：自有商品数据 + 竞品数据
列表。输出分析报告包含：价格区间对比、核心卖点差异分析、用户评价情感倾向对比、
市场定位建议。使用竞品分析 Prompt 模板，支持自定义分析维度选择。

关联子功能：
· 承 F-304 竞品可信实体、内容证据与监控——分析输入只取已批准 match 绑定的
  价格、卖点与脱敏聚合口碑
· 承 F-307 指标语义与经营诊断——价格差异等可量化维度按其口径由代码计算，
  结果带定义版本与证据数量
· 承 F-305 商品与渠道 SKU 事实模块——自有商品侧数据取自版本化商品事实

```
