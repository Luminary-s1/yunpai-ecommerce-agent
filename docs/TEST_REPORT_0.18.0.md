## 5. 评测准确性与负向验证

浏览器使用两条最小合成用例验证了正负路径：

1. v1 含一个多轮 case，候选 `candidate-1` 为 1/2 通过；意图准确率和证据覆盖率均为 50%，失败精确定位到 `turn_2:intent_mismatch`。
2. 由 v1 创建不可变 v2，修订第二个 case 并重新冻结；候选 `candidate-v2-browser` 为 2/2 通过，通过率、意图准确率和证据覆盖率均为 100%。
3. v2 选择 v1 失败 run 作为基线，可比基线为 1 条、回归率 0%，后台正确显示定义变更排除和无回归用例。

这组数据只验证功能链，不代表客户业务准确率。正式 Gate 默认至少 20 条，且应由客户标注集覆盖咨询、订单、物流、售后、风险、转人工、证据和模型故障场景。

## 7. 浏览器验收

在真实运行的 `0.18.0` 服务上完成管理员登录、suite 创建、JSON 批量用例替换、冻结、实际 Agent 失败运行、新版本克隆、再次编辑/冻结、基线选择和通过运行。运行详情正确显示 Gate、场景通过率、失败用例、可比基线、定义变更排除和回归列表。

初次桌面检查发现页面有约 30px 全局水平溢出，定位为表单输入和长 hash/JSON 文本没有收缩/换行。增加字段宽度约束和任意换行后，1280px 视口 `body.scrollWidth=1265 <= innerWidth=1280`，无全局水平滚动。DOM 检查未发现控件重叠。

本轮 in-app Browser 的 viewport API 未生效，因此没有把 390px 标记为通过；CSS 静态约束已保留，但仍需移动设备或可控视口环境复验。

## 10. 发布建议

建议将 `0.18.0` 作为本地/客户环境评测候选：允许部署隔离环境、导入脱敏样本、执行真实 Agent 回归、验证只读事实和运行 shadow。生产 `automatic` 保持关闭。只有上表 Gate 都有可复核证据并经业务、安全和运维签收后，才创建新的发布版本进入 assist/collaborative 灰度。
