## 7. 本机只读性能

环境：本地 Uvicorn 单实例、SQLite WAL、1 条价格观察、2 条匹配、2 条口碑信号、关闭真实模型和后台 worker。顺序请求每个接口 100 次：

| 接口 | p50 | p95 | max | 错误 |
|---|---:|---:|---:|---:|
| `/v1/competitive/analysis` | 84.34 ms | 95.26 ms | 97.35 ms | 0 |
| `/v1/competitive/matches` | 75.18 ms | 87.12 ms | 101.97 ms | 0 |
| `/v1/competitive/quality` | 75.48 ms | 88.14 ms | 95.97 ms | 0 |

分析接口 16 并发、200 次：吞吐 64.8 rps，p50 239.73 ms，p95 320.29 ms，max 361.46 ms，0 错误。默认限流专项实际返回过 `429 Too Many Requests`；性能样本在独立进程临时提高限额后执行。

这些数字只证明小数据本机冒烟，不是容量上限或生产 SLA。未覆盖万级竞品历史、真实网络、数据商延迟、多进程写入和目标硬件资源竞争。

## 8. 本轮发现并修复的问题

| 问题 | 风险 | 修复 |
|---|---|---|
| 价格观察直接相信 SKU 对应关系 | 非同款价格产生错误建议 | 同款候选、解释评分和人工裁决门 |
| 未批准数据进入 Agent | 模型可能把猜测当事实 | Agent 输出二次过滤和 quality gate |
| 匹配撤销不影响既有告警 | 已知错误仍持续提醒 | 裁决后立即原子重评并自动解决失效告警 |
| 口碑可能保存原始评论/身份 | 隐私和许可风险 | 仅结构化聚合摘要、最小样本、extra forbid、写前脱敏 |
| 匹配查询逐条读取状态 | 历史量增长后出现 N+1 | 观察查询一次 LEFT JOIN，分析限制 5000 条 |
| schema 测试写死 v16 | 灾备和 CLI 回归失败 | 全部更新为 v17，并新增 v16 前向迁移保留测试 |
| 旧监控策略静默改语义 | 升级后告警突然消失 | 历史默认兼容，新策略默认 approved-only，后台显式显示 |

## 10. 发布建议

0.17.0 可作为合法授权数据的只读导入、同款人工治理和 shadow/assist 竞品 Agent PoC 基线，不应直接对正式商品执行调价或内容修改。先用客户标注集校准匹配规则，再以真实只读数据运行至少 24 小时，抽检错误匹配和告警；业务、安全、数据和运维共同签收后再决定下一版本。
